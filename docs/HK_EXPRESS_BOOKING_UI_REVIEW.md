# HK Express 官网订票 UI 分析与会员页改进规格

> 状态：现行 · 对应代码：`frontend/members/index.html`、`frontend/members/portal.js`、`frontend/members/portal.css`

调研日期：2026-11-15（Asia/Shanghai）。实施分支：`feature/member-demo-journey`。本文件服务于产品设计、前端实现和现场演示，不能代替航空公司的票价规则。官网会按语言、设备、活动及时间变化。

## 1. 结论与本次目标

官网值得借鉴的是任务顺序：先选路线与日期，再理解航班及票价，最后确认订单。会员页应把“我能去哪一天、这一程总共多少钱、现在点击会发生什么”放在最显眼的位置。品牌色可以帮助辨识，但不应以更大的宣传区挤占订票操作。

本次采用紧凑搜索面板、实际可售日期价格条、含费用总价层级、明确的结算进度和可持续访问的操作区。保留 UOption 独立品牌及会员业务，不复制 HK Express 商标、营销图片或票价产品名称。此前用户要求删除的往返推荐和双程计划继续保持移除。

## 3. 官网搜索 UI：逐项观察

### 3.1 整体信息层级

主站包含品牌导航和促销内容，搜索区是独立的白色面板。订票系统的页面更集中于任务：顶部保留品牌、地区语言、货币和账户入口，中间是搜索面板，周围留有空白。紫色按钮与选中下划线帮助用户识别当前操作。

面板的业务标签区分预订、管理订单、值机和航班状态。这些是不同任务，不宜在同一表单中混合。我们只提供订票、会员和已购行程三个真实可用入口。

### 3.2 搜索字段的顺序

第一层是行程类型、人数、可选优惠码；下一层是出发地、目的地、日期和搜索按钮。它与旅客思考顺序一致，用户不用先理解系统模型。

本项目固定单程、一位会员、HKD，因此将这些作为清楚的范围说明，不渲染无法操作的往返、人数或优惠码控件。路线和单日出发时间成为主行；国家地区及日期范围放入下方可折叠的灵活搜索区。本版默认展开以保持原有搜索习惯，用户可自行收起。

### 3.3 机场选择

订票系统的机场列表按国家／地区分组；选项同时显示城市／机场名称及三字码，例如东京羽田 HND 和东京成田 NRT。主站搜索面板还展示双向交换图形。

本项目沿用原生 select 与 optgroup：保留键盘和移动系统选择器，提供可见标签、机场全名及三字码。新增互换起终点按钮。互换会清空目的地国家筛选以免筛选冲突，但不会自动提交搜索；修改仍需点击 Search flights。目录存在某个机场不等于该机场已有会员票。

### 3.4 日期与价格

实测日期弹层显示连续两个月、月份切换、不可选过去日期和每日参考起价，底部明确起价口径与币种。价格和日期结合，可以帮助用户在日期有弹性时作比较。

本项目没有全航网每日库存，因此不制作填满日期的“真实票价日历”。我们新增实际可售日期条：仅聚合当前已发布、可购买且此用户尚未买过的航班。每个日期显示该日最低含费用机票价，会员费不混进票价。没有库存的日期不捏造价格，也不承诺整个航网没有航班。

日期条遵循已经提交的路线条件，但有意不限于原日期范围，作为改期入口；旁边明确说明选择日期将替换原范围。点击时恢复已提交的路线，避免把尚未提交的草稿条件偷偷加入结果。日期采用日历字符串，不用浏览器时区把日期移动一天。

## 4. 从搜索到完成：流程对照

| 阶段 | 官网证据 | 会员页具体行为 |
|---|---|---|
| 搜索 | S1、S2 实测 | 路线、单日、灵活范围、显式提交 |
| 比较日期／票价 | S2 日历，S3 流程 | 实际日期最低含费价；按日期、含费总价或基本票价排序 |
| 选择航班 | S3 流程，结果页未实测 | 日期、路线、已有起飞时间、会员配额、基本价及分项费用 |
| 旅客与附加项 | S3、S4 说明 | 固定一位会员；不收真实护照、联系人或支付数据，不展示假行李／座位加购 |
| 确认 | S3 流程；布局为本项目设计 | 先核对费用，非会员明确入会，再独立确认机票 |
| 完成 | S3 流程；本项目已有实现 | 模拟确认状态、订单编号、My trips；可在成功后查看可售回程 |

会员入会与购票是两个事务，不能把按钮文案写成一次买完。会员费收取后仍可能没有票，选择航班或加入会员不锁位。现有库存／报价复核和成功后刷新失败的恢复逻辑必须保留。

## 5. 票价与权益的信息架构

S4 通过多种票价档次让用户比较行李及选座等权益。可借鉴“选择前看清权益”，但我们的会员产品只有一种可售票价，不能复制四个无后端支持的档位。

航班卡片采用以下顺序：

1. 出发日期、路线、机场名称、已有起飞时间和可售会员位。
2. 会员基本票价。
3. 燃油及政府／机场费用分项；适用时额外显示电子支付费。
4. 更显眼的单程机票总价，以及非会员首次购买含会员费的金额。
5. Select flight 操作。选择进入核对，不直接扣费或占位。

官网起价展示与我们的设计选择应明确区分：我们主动加强含费总价层级，避免评委只看到低基本价而误以为那是最终付款额。保留基本价可以解释定价模型的输出，税费则是额外组成。

S5 把 YR 用于燃油／航空公司附加费；政府税、机场费有独立代码。本项目继续按核验后的分类展示，不把所有其他费用称作 YR，也不虚构单列 YQ 金额。详细来源、日元原币及换算日期折叠于结算明细，便于按需核查而不淹没主任务。

## 6. 当前会员页的问题与改动映射

| 原问题 | 对用户的影响 | 本次实现 |
|---|---|---|
| 宣传主视觉和会员卡过高 | 搜索与真实库存出现在页面很下方 | 改为简短订票标题和紧凑会费摘要 |
| 出发地、目的地、精确日分在不同层 | 路线设置需要来回寻找 | 放在同一主搜索区；增加互换按钮 |
| 灵活范围、精确日看起来同等重要 | 不清楚最短搜索路径 | 主行使用精确日，下方独立灵活区 |
| 只有日期输入，没有库存线索 | 容易查到无票日期 | 可售日期含费价格条，可横向滚动 |
| 主要只按基本价比较 | 不同机场税费下可能选错更贵的总价 | 新增 Lowest ticket total 排序，保留其他排序 |
| 全额付款信息分散 | 不清楚机票与会费各是多少 | 强调机票总价，结算中分开列会员费及首次合计 |
| 长来源说明把按钮推离视野 | 手机端需要长距离滚动确认 | 对话框内固定底部操作区，说明默认折叠 |
| 搜索结果缺少明确返回入口 | 用户不易找到修改条件位置 | 结果摘要旁增加 Edit search 并聚焦出发地 |
| 购买阶段不够清楚 | 易把入会当成完成购票 | 结算进度强调当前 Membership 或 Confirm ticket 阶段，成功后隐藏步骤 |

## 7. 桌面与移动布局规格

桌面使用紧凑横向主搜索区：出发地 → 互换 → 目的地 → 日期 → 搜索。下方灵活区域三列排列。结果左侧展示航班，右侧保留真实会员信息；宽屏时会员说明保持在可见区域。日期条超出宽度时仅局部横向滚动，不能撑宽整页。

较窄屏幕把日期及搜索按钮换行；手机上路线保留两个端点，日期和主按钮各占一行，范围字段按两列排列。票价区移到路线下面，费用每项单独一行。结算对话框限制在视口内，可垂直滚动；底部确认区保持可访问，不遮住最后一段内容。

使用现有紫、青、白色系统：紫色表示主要操作和金额，青色用于辅助边界；错误同时有文字而不是只改颜色。保留系统字体、不增加外部字体或营销图片请求。减少动态效果，并尊重 prefers-reduced-motion。

## 8. 状态、错误与无障碍

- 输入框有可见 label；交换按钮有文字 aria-label，不能仅依赖箭头。
- 日期条使用原生 button 和 aria-pressed；当前结算阶段用 aria-current=step。
- 所有日期输入仍使用原生控件。年份越界、范围逆序保持就地错误，隐藏在灵活区域内的无效字段需自动展开。
- 修改草稿不改变当前结果。结果摘要与实际筛选状态一致。
- 无发布航班、无匹配、全部售罄分别给出可执行提示；可售日期条在无数据时隐藏。
- 过期会员、忙碌状态、已购航班不允许重复提交。结算错误保持原订单和最新服务器信息。
- 成功写入后即使账户刷新失败，也保留成功提示；刷新按钮不重复发送购买请求。
- 固定底部不能遮挡键盘焦点或阻止读取费用；桌面与 390px 手机都应验证。

## 9. 数据与模型边界

本次是订票界面的改进，不更改 NHPP、P90 保护、会员价格优化或放票算法。日期最低价使用 API 当前返回的真实模拟库存总价，非预测价格。机场目录、合成时间及收费参考继续明确属于原型；不虚构到达时间、飞行时长、行李权益或售罄倒计时。

6 班香港与日本演示票保留。费用估算仍按 S6 的收费快照，不能拿界面变化声称进行了新模型训练、真实旅客实验或获得更高利润。

## 10. 验收清单与现场演示

| 检查 | 预期 |
|---|---|
| 首屏 | 简短标题后即可看到搜索，不出现往返推荐 |
| 路线交换 | HKG / NRT 变为 NRT / HKG；国家筛选清除，未自动提交 |
| 日期条 | 只列实际可售日期，显示含费最低价；点击后只显示该日与已提交路线 |
| 价格排序 | 根据 API total 排序，基本价与总价顺序不同的 fixture 能检出错误 |
| 结算 | 分项、票价合计、会员费、总计相符；确认按钮可见并使用原交易 API |
| 异常 | 报价变化、库存变零、刷新失败和重复购票仍受保护 |
| 移动与键盘 | 无整页横向溢出；原生控件可操作、焦点可见 |
| 文档与模型 | 文档索引有效，冻结证据校验通过 |

建议现场演示顺序：选 HKG → NRT；查看实际可售日期；核对基本价、YR、机场税费和总价；点击 Select flight；说明首次会费与机票分开确认；展示模拟确认和 My trips。真正购买会消耗演示库存，自动化验收使用隔离 fixtures，不消耗现场的 10 个座位。

## 11. 后续可扩展事项

未来如有真实产品需求，可增加机场自动补全、真正的月历库存、往返原子订单、可验证行李权益及旅客资料收集。这些都需要对应的数据和后端交易设计。当前优先保持一个短、清楚、可验证的单人会员购票路径。
