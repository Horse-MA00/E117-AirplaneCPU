# 需求篩選、原價起點及收益範圍

更新：2026-11-14。這份文件說明最新 Admin 行為；早期 15% 起點的資料與實驗保持原始內容，不能與新實驗混稱同一價格策略。

## 1. 高／中／低需求代表甚麼

Forecast seats 與 Optimize prices 的 Demand 篩選器使用同一份航班分類。可選 All、Low、Medium、High，以及沒有有效分類的 Unclassified。保留可見且有效的航班選擇；沒有符合項目時顯示空狀態並停用依賴航班的操作。

分類基準固定為 **D28 時能看到的歷史，經 NHPP 預測的起飛時正常訂位率**：

```text
預測正常訂位率 = 1 − 預計起飛空座數 / 航班容量

Low：    訂位率 < 60%
Medium： 60% ≤ 訂位率 < 85%
High：   訂位率 ≥ 85%
```

這些門檻是本原型的瀏覽分類規則，不是航空業認證門檻。D28 的「正常」需求基線不包括未來會員促銷交易。分類不使用 `scenario`、`final_booked`、`final_empty_rate`、未來快照或隱藏生成參數，因此不會把已知模擬結局當成當時的預測能力。

選擇 D14／D7 或調整 Forecast 日期後，分類仍明確標示為 **D28 forecast**，便於在兩個頁面使用相同航班群。所選時點的 NHPP 預測、可用庫存及放票數照常重算；分類不能取代即時預測。Low 也不保證有可發配額或正增量收益，因為風險保護、發布比例、舊有效配額及會員已售量另行計算。

後端預先計算目錄分類，避免每次打開下拉選單都重新跑完整航班目錄的 NHPP。索引附資料、模型及校準來源指紋；缺失或來源不匹配時，對應航班以 Unclassified 顯示，不使用過期分類或從情境名稱猜測需求。

本次索引涵蓋 1,549 班：Low 336 班、Medium 447 班、High 766 班。這是合成目錄的分類數量，不是實際航司需求比例。需要重新生成時執行：

```sh
python scripts/build_demand_catalog.py
```

生成器先後檢查來源指紋並原子替換 `simulation/demand_catalog.json`，不改寫原始資料。更換資料／模型或重建索引後須重啟服務；航班目錄沿用既有程序內快取，沒有宣稱熱更新。Docker 使用者重新建置並啟動容器，以載入新程式和索引。

API 航班欄位包含：

| 欄位 | 意義 |
| --- | --- |
| `demand_band` | `low`、`medium`、`high` 或 `unknown` |
| `demand_reference_day` | 固定為 28 的分類參考日 |
| `demand_expected_load_rate` | D28 預測的起飛時正常訂位率；無有效分類時不捏造數值 |

分類只幫助選擇實驗航班，不進入 NHPP 特徵、旅客購買意願或優化器收益計算。

## 2. P₀ 改用正常基本票價

新主流程版本為 `flight-policy-feedback-v4-original-fare`。新實驗從所選航班、所選 D28／D14／D7 時點最近可見的 `normal_base_fare` 開始：

```text
P₀ = 當時最近可見的正常基本票價
```

例如正常基本票價 HK$560，初始候選就是 HK$560，不再是 HK$84。燃油費、稅費及其他必付費保持分開；「原價」在這裡指基本票價，不是含稅總付款。起點只是一個待測候選，並非已推薦的最終會員票價。

如果所選時點沒有有效報價，程式只會向較早、當時已可見的報價回查並保留報價年齡；不讀未來報價或把缺值改成零。P₀ 仍是唯讀，由伺服器決定。前端搜尋上限須容納該起點，避免原價高於舊 HK$500 上限時，無法開始原價搜尋。

V₀ 仍由使用者設定，並在單次價格比較中固定；數學與 LLM 軌分別比較候選。這項修改沒有引入自動全年會費優化。NHPP 本體與凍結校準、D28／D14／D7 放票規則、每輪扣除前輪有效未售配額的方式保持不變。

舊資料中的 `member_initial_base_fare` 及舊報告 P84／V399 等價格是歷史紀錄。原始 gzip、模型評估、實驗帳本及 provider 輸出不為新政策而回填或重算。新主流程使用正常基本票價，與這些歷史起點分開。

## 3. 單航班貢獻不能代表整個會員期

目前主流程模擬一班指定航班。會費仍實收全額一次，主比較採用三分之一新會費／會員服務成本的單航班分攤，另外保留完整本次現金視圖。

「後續收入」要區分兩件事：**所選航班從 D28／D14／D7 到停售、起飛之間的後續正常票及會員票銷售已在市場時間線內模擬**，並非只算選定當天的交易。尚未模擬的是會員日後搭乘其他航班的收入、成本及未來實付續會。不能把這兩種範圍混為同一個缺漏。

因此，歷史首爾實驗的 −HK$2,364 是 **該次單航班分攤後，相對無優惠對照的差額**。−HK$1,380 則是同一批已模擬事件、改用本次全額會費現金的差額。這兩個數字都不能回答會員之後多飛幾次、帶來附加消費或續會後，整個計劃是否盈利。

| 評估內容 | 主流程目前的涵蓋範圍 |
| --- | --- |
| 選定航班從實驗起點至停售／起飛的正常票、會員票、取消及附加收入 | 已模擬、計入帳本，包括當天之後的交易 |
| 已模擬交易的載客、附加服務、會員服務及計劃成本 | 已計入 |
| 新收會員費 | 全額現金保存；主比較依既有單航班假設分攤 |
| 同一會員之後其他航班的收入和成本 | 尚未建模，不能當成零或任意補收入 |
| 後續旅程替代原正常票的影響 | 尚未在這個單航班流程評估 |
| 未來實付續會 | 尚未建模；意向不等於已收款 |
| 完整會員期的增量盈利／最優會費 | 不能由單航班結果推導 |

`NO_OFFER` 的正確讀法是「這次單航班測試沒有接受候選」。UI 的收益提示及決策名稱須維持這個範圍，不把它呈現為整個會員方案失敗。

讀取單航班實驗時，API 額外返回 `economic_scope`：`kind` 是 `selected_flight_attributed_contribution`，`membership_term_evaluated` 為 `false`，`future_member_trip_contribution` 及 `future_renewal_contribution` 為 `null`。這些欄位描述已有結果的範圍，沒有回填改寫歷史帳目。

完整會員期需要另一個持續市場：同一批旅客保留會員狀態、預算及記憶，多班航班按共同時間推進；會費只收一次，每次行程與取消都計入收益和成本。最後與同一批旅客沒有會員方案時的完整期間對照比較。後續收入必須連同成本與正常票替代一起評估，不能只加有利的收入。

倉庫保留較早的多航班／完整期間參考工具，但它們的客群、供應及規則與目前單航班主流程不同，不能直接將其利潤拼到單航班結果。這次篩選及起點更新尚未把主流程改為完整會員期市場。
