## 審查中發現並修正的問題

- 需求保護的晚期積分缺少指數位移：修正為未來區間的尾段積分。
- D7分析仍產生D28事件與過去開放策略：依as-of限制事件與可選開放日，D0永遠NO_OFFER。
- 市場的預期旅行頻次和正常請求分配不一致：改用同一組事前頻次權重與正常需求率。
- 原始P90在第一次診斷集低覆蓋：建立獨立校準／測試分割，保留原始分位數，不在最終測試上反覆調參。
- HTTP handler helper與標準庫self.headers衝突：重新命名並加入實際HTTP smoke測試。
- 前端票價、空座率欄位不一致：對齊normal_total_fare和empty_rate。
- 前端票價展示漏掉fees、付款確認未顯示total：修正完整價格讀取。
- 成本輸入使用不被引擎讀取的別名：改為incremental_cost，避免看似可調但計算未改變。
- 候選最早D14卻可能在D28套用：限制提早採用；不同會員期的研究結果不能冒充一年示例會員產品。
- 購票競態及重複購買：SQLite BEGIN IMMEDIATE、唯一(flight,customer)限制與同時購票測試。
- 跨模擬日期重設同航班庫存：阻擋已有優惠航班切換as-of再次發位。
- 短會員期同人同日重複飛行：在共用世界生成階段按旅客／日去重，兩個方案使用同一批合法出行機會。
- 多次重播的拒絕原因保留第一輪文字：改成按全部重播的可行性生成原因。
- D1優惠24小時會超過22小時售票窗：有效期縮至停售。過期會員明確拒絕續期，避免回傳已失效的會員。
- 授權API重新導向可能轉送header：OAG／LLM均停用redirect，新增mock測試；provider失敗不露出原始錯誤內容。
- 憑證外洩：金鑰只在忽略的.env.local；OAG原始回應和私有快取不進Git；使用者授權的合成LLM實驗以去憑證audit公開，前端無憑證。

## 第二輪新增的實作與方案改變

| 原來的做法 | 新做法 | 實驗帶來的意義 |
|---|---|---|
| 所有航班固定較長NHPP窗口 | 保留較長窗口，偵測水準轉折後重估；另抽未知未來跳變路徑 | 七日窗口消融反而惡化，因此沒有一律縮短窗口 |
| 刪除達容量的計數 | 右截斷Poisson likelihood；沒有可售曝光的零值不當零需求 | 觀測語義較正確，但會員於區間內搶完位的exposure仍待建模 |
| 同一舊holdout重複看分數 | 凍結模型，新240班final及額外1200班擴大驗證 | 保留變差的MAE及子群缺口，沒有挑選最佳報告代替舊證據 |
| 舊定價器用beta重建尾段 | 讀取v2同一路徑的demand_curve/protection_curve | 避免丟失跳變混合分布對時序和保護量的影響 |
| 單次訂閱／購票prompt | 六階段、預算／會員／退款狀態，並保留raw request/response | Codex168份與DeepSeek672份基線決策可以回溯 |
| 每個旅客有自己獨立庫存 | 共用事件隊列、同一航班扣位、同行整單、等待不保留座位 | 一人的購買改變下一個人的選項 |
| LLM只輸出人物理由 | LLM選action，程式驗證並寫入同一帳本 | LLM決策會改變政策的貢獻與服務率排名 |
| 市場需求由預測均值重新抽樣 | 獨立生成真實模擬到達路徑；模型只讀as-of歷史 | 能測預測錯誤及持續跳變，沒有用預測器替自己製造答案 |
| 不同頁使用不同票價／供應 | 共用市場頁以同一config顯示政策、旅客、航班與財務 | 192組快速搜尋保留為篩選器，進入新世界後只稱候選 |
| 一張票推論年費 | 每人多次出行、有限航班目錄、已購會員觀察至有效期結束 | 實際模擬用票計入成本，無交易的續會意向不入帳 |
| 全候選都呼叫LLM | 少量預先指定對照政策，跳過唯一合法行動 | 控制成本；新呼叫、快取、強制行動和失敗分別報告 |
| 只驗JSON合法 | 新呼叫重複、排序、中英文、完整價格配對probe | 60份有效DeepSeek probe中仍有3/12重複組不一致 |
| 單批數據 | 原20萬＋新40萬筆，40種子市場重播及獨立LLM驗證 | 更大樣本找出了替代航班退款截止的實際bug |

## 第二輪審查修正

- 早期旅程packet把未來change_scenario提前透露，並讓非會員看到120日剩餘期：v2.1修正；原始pilot檔不改寫。
- 新配置金鑰後發現前端live選項HTML標籤損壞，令初始化中斷：修正並以真實已配置服務的瀏覽器流程驗證。
- 共用市場初版只檢查confirmed訂位便提供取消，忽略替代航班的實際2小時截止：擴大測試seed20261234重現；v2按實際已購航班判斷。保留交易層的第二次驗證及修正前紀錄。
- 長實驗的原始audit會超過5000筆inline限制：離線報告／公開匯出改為streaming，Web小型檢視保持有界。
- 憑證清理每次遞迴都掃環境變數造成匯出緩慢：改為每次頂層呼叫只取一次清理表；不改變遮蔽規則。
- 確定性重播每步都寫完整世界成本過大：分段checkpoint；live決策仍逐步保存，輸出來源與重播清楚標記。
- 跨seed比較不應挑最賺的一個個案：顯示成對差額均值、完整seed排名和穩定性，只有全部政策完成且帳本檢查通過才排名。
- 正常票轉會員的同人同旅程替代另作描述統計；差額已在成對帳本中，不再扣一次「蠶食損失」。
- 最終審查發現實驗凍結清單列的是v1校準檔，而實際NHPP讀取v2檔：改為記錄實際v2檔，缺少版本來源時禁止續跑。既有實驗未改寫；另附與已推送b131fe5完全相同的檔案hash證明及事後證明限制。
- 正在追加的audit可能在下載快照時只寫完半行：gzip串流只輸出完整JSONL，新增中途追加的回歸測試。

## 最新三輪放票規則的調整

- 放票時點固定為D28、D14、D7，價格搜尋維度由192組降至64組。舊報告中的開放日與192組是歷史設定，不能套用到新版本解讀。
- 舊共享市場會在重算時直接設定`member_remaining`，新版逐輪保存配額批次，只補足「本輪未售目標－前輪有效未售量」的正差額。第三輪合計扣除第一及第二輪剩餘，售出會員位只在物理佔用扣一次。
- 舊SQLite示例以不同as-of日阻擋跨日發位；新版改為合法輪次單調前進、每輪只發布一次及交易鎖內檢查，支援同班三輪而不重複增發。
- 每日需求預測與配額發行分開；D13仍可顯示新的風險預測，但本輪可新增為0。購買與取消更新實際狀態，取消不自動補回已消耗批次。
- 若前輪未售量高於最新目標，只停止新增並限制實際可成交量，不透過覆寫歷史掩蓋超額承諾。前端分開顯示名義未售配額及可售供應。
- NHPP、校準、原始LLM回應及完成實驗的manifest維持原樣。新放票版本另作回歸與市場驗證，舊v2的收益排名不視為新規則成績。完整規則及案例見[THREE_ROUND_RELEASE.md](THREE_ROUND_RELEASE.md)。

## 仍需披露的限制與下一步

1. **真實校準仍缺。** 所有60萬列為合成數據，OAG Flight Info沒有每日訂位／報價或會員曝光轉換。優先取得真實計數、可售曝光、購買請求及促銷紀錄。
2. **未知未來突增不可由相同歷史辨認。** 混合風險先驗與保守保護量能改善部分覆蓋，不能預知事件；較高釋位也提高擠出正常客的風險。保留D28需求MAE退步及D7子群缺口。
3. **會員造成區間內售罄的exposure。** 如果會員在區間內用完位，正常gross=0不等於整日零需求。現時不超賣，但取消後的後續需求估計可能偏低。後續應記錄事件級可售時間並建立新的模型／校準版本。
4. **LLM不是需求真值。** 固定temperature不保證選擇相同；60次probe沒有排序或語言翻轉也不證明無偏。以真人同題實驗與試點交易校準，再估價格反應。
5. **有限目錄範圍。** 目前6–12班、有限已知出行機會；不是整個HK Express真實航網。基線以HKG出發為主，完整入境／來回聯程、競爭航司及全年未知新增出行仍需擴展。
6. **財務口徑。** 顯示貢獻包含增量載客、行李、會員服務和計劃成本；必付費為明示代收代付假設。沒有完整固定機隊成本、實際稅務或正式收益確認，因此不稱航空公司淨利。
7. **正式部署。** 本地服務與模擬SQLite不能公開當生產系統；需要身份授權、工作排程／限額、真實庫存、secret manager及票務整合。現時沒有真實付款或出票。

驗證與實際實驗完成狀態以`ITERATION_2_PROGRESS.md`及共享市場驗證報告為準。NHPP詳細證據、LLM基線和probe資料均有原始檔，不將假設包裝成真實客群結果。


## 英文場景與幣別修正（2026-11-14）

- 原旅程prompt允許人物語言，與英文介面的目標不一致；現在人物背景語言保留、回覆語言固定英文，費用固定HKD。數值、人口抽樣序列、NHPP及三輪放票規則未改。
- 額外提供會費前後的完整同行價格比較與單趟預算範圍，減少模型把會費／票款或年度期望混算。因此這不只是文字翻譯，新舊選擇不能作語言單一因素比較。
- 防止拒絕後的錯誤回覆進入快取或改變狀態；原始回覆保持可查，歷史suite及新suite以版本／prompt hash分開。續跑其他模型名稱的約束仍可加強，現有journey suite只核對prompt版本／hash，正式研究應同時凍結provider model及所有生成器原始碼。
- 字元及常見幣別檢查不是語義正確性證明；實際30回覆驗證全部英文HKD。後續應用同題真人選擇與盲測檢查偏好，而不是把這批模型入會率當成市場ground truth。
