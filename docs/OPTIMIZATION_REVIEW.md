## 審查中發現並修正的問題

- 需求保護的晚期積分缺少指數位移：修正為未來區間的尾段積分。
- D7分析仍產生D28事件與過去開放策略：依as-of限制事件與可選開放日，D0永遠NO_OFFER。
- 市場的預期旅行頻次和正常請求分配不一致：改用同一組事前頻次權重與正常需求率。
- 原始P90在第一次診斷集低覆蓋：建立獨立校準／測試分割，保留原始分位數，不在最終測試上反覆調參。
- HTTP handler helper與標準庫self.headers衝突：重新命名並加入實際HTTP smoke測試。
- 前端票價、空座率欄位不一致：對齊normal_total_fare和empty_rate。
- 前端票價展示漏掉fees、付款確認未顯示total：修正完整價格讀取。
- 成本輸入使用不被引擎讀取的別名：改為incremental_cost，避免看似可調但計算未改變。
- 候選最早D14卻可能在D28套用：限制提早採用；不同會員期的研究結果不能冒充一年示例會員產品。
- 購票競態及重複購買：SQLite BEGIN IMMEDIATE、唯一(flight,customer)限制與同時購票測試。
- 跨模擬日期重設同航班庫存：阻擋已有優惠航班切換as-of再次發位。
- 短會員期同人同日重複飛行：在共用世界生成階段按旅客／日去重，兩個方案使用同一批合法出行機會。
- 多次重播的拒絕原因保留第一輪文字：改成按全部重播的可行性生成原因。
- D1優惠24小時會超過22小時售票窗：有效期縮至停售。過期會員明確拒絕續期，避免回傳已失效的會員。
- 授權API重新導向可能轉送header：OAG／LLM均停用redirect，新增mock測試；provider失敗不露出原始錯誤內容。
- 憑證外洩：金鑰只在忽略的.env.local；OAG原始回應和LLM快取不進Git，前端無憑證。

## 真正尚未驗證或未實作的部分

- 未提供LLM provider金鑰，live呼叫尚未實測；不能稱已用LLM跑完整真實客群。已完成提示、兩階段接口、校驗與數學模擬。
- 200000列並非真實HK Express訂位或價格。OAG Flight Info沒有提供本項目缺少的購買反應ground truth。
- 校準後獨立合成覆蓋83.89%，持續突增子群47.62%，仍有過度釋位風險。偵測到當下突增可停發，但未知未來事件無法保證預知。
- 定價採有限合成航班目錄；沒有完整真實航空網絡、競爭者反應、續會、完整退款／改期、團體整單或生產航空票務。
- 會員展示固定365天；其他期限只能作定價研究，不直接套用到展示會員。
- 本地標準庫server不是公開部署架構；未實作登入權限、支付、PNR、真實出票或正式客戶資料接入。

## 下一輪按價值排序的改善

1. 取得正常訂位快照、促銷與價格歷史，及實際會員報價曝光／購買紀錄。先校準需求與選擇，再擴大模型。
2. 用截斷似然取代刪除售罄區間；測試分段NHPP／變點與短期脈衝，明確區分正常增長、團體訂位與促銷。
3. 擴大未見需求機制測試，按可觀測特徵設保護量；重新設立未碰過的測試集，不能繼續調整目前holdout以提高分數。
4. 讓真人在完整會費、條款與可用性下選擇，對LLM人物和數學需求做校準；問卷意向仍需試點交易驗證。
5. 將價格市場換成有日曆、路線、同行數及取消的共用事件引擎，加入拒單與替代航班，讓會員可用性更接近實際。
6. 若候選擴至連續或更多維度，對照網格基線加入TPE；先保持同客群配對與獨立測試。
7. 真正部署前加入身份、角色、授權、限流、工作佇列及後台庫存整合；憑證由secret manager管理。
